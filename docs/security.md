# Безопасность и восстановление Folder Camera

Документ описывает архитектуру форка на примере [стабильной сборки 29](https://github.com/Aleks1496/folder-camera/releases/tag/folder-camera-build-29). Подробности обмена данными приведены в [описании протокола](protocol.md).

## Хранение на компьютере

CLI и настольные интерфейсы используют общий движок. В Linux и macOS он публикует готовый файл через жёсткую ссылку без перезаписи и синхронизирует файл и каталог. В Windows движок сбрасывает данные файла на диск и использует системное перемещение с записью на диск и запретом замены существующего файла. На Windows целевая файловая система для этих гарантий — локальный NTFS. Синхронизация каталогов через `fsync` в Windows не поддерживается.

Временные файлы приёма и записи о доставке хранятся отдельно. При запросе квитанции движок проверяет фактический размер и SHA-256 сохранённого файла. Если путь назначения занят, приёмник возвращает ошибку. На Windows однозначно совпавшая подпапка используется с её фактическим именем, даже если запрос отличается регистром. При неоднозначном совпадении имён приёмник возвращает конфликт.

Движок проверяет корневые и промежуточные каталоги, состояние и файлы назначения через `lstat` и проверку фактических путей. Символические ссылки и обнаруженные перенаправления каталогов отклоняются. Эти проверки не выполняют все операции относительно открытого дескриптора каталога. Между проверкой и открытием пути другой процесс с правом записи может изменить проверенный каталог. Папку снимков, её родительские каталоги, каталог временных загрузок и папку состояния следует размещать там, где их не могут менять недоверенные локальные пользователи и процессы. В Windows стандартная папка состояния наследует права профиля. Для собственного расположения через `--state` нужны эквивалентные ограничения доступа.

Корень снимков по умолчанию — `~/Captures`. Папка состояния отделена от дерева снимков. По умолчанию это `$XDG_STATE_HOME/folder-camera` или `~/.local/state/folder-camera` на Linux, `%LOCALAPPDATA%/FolderCamera` на Windows и `~/Library/Application Support/FolderCamera` на macOS. Deno Desktop на macOS также поддерживает найденный прежний профиль. При использовании собственного профиля сохраняйте параметр `--state` между запусками.

Перед началом приёма движок сохраняет папку, порт и режим выбора адреса в `receiver-config.json`. Если стандартный порт занят, приёмник может выбрать следующий свободный. Явно заданный порт должен быть свободен. Для квитанций старых версий без сохранённого корня требуется один раз указать исходную папку снимков. Блокировка ОС защищает папку состояния от одновременной записи несколькими экземплярами и освобождается при завершении процесса. Файл блокировки должен оставаться на месте во время работы.

## Сеть и управление приёмником

Приёмник подбирает частный адрес по локальным интерфейсам и данным маршрутизации. Для выбора адреса используется только информация компьютера. Известные туннели, VPN и внутренние сетевые интерфейсы отфильтровываются. В Windows внешний интерфейс Hyper-V вида `vEthernet (sw)` может использоваться, а Default Switch и WSL исключаются. Если пригодный адрес отсутствует, приёмник сообщает об ошибке. Частный адрес можно указать вручную.

Пакет Windows x64 включает окно Windows Forms и отдельный движок. Окно управляет запущенным им дочерним процессом через стандартные потоки ввода и вывода. Для открытия уже запущенного окна используется именованное событие Windows в локальном сеансе. Сетевой порт движка обслуживает протокол сопряжения и передачи снимков.

В интерфейсе Deno Desktop отдельный слушатель на loopback раздаёт встроенные ресурсы и работает с нативными привязками окна. Локальный API управления на другом loopback-адресе требует токен из закрытой папки состояния и отклоняет запросы с заголовком `Origin`. Через него доступны активация окна, статус, создание кода сопряжения, просмотр списка устройств и принятых снимков, отзыв устройства, запуск и остановка приёма. Подробности приведены в [документации Deno Desktop](desktop-receiver.md#local-control-api).

При первом запуске без подключённых устройств приёмник автоматически создаёт одноразовый QR-код. Повторное сопряжение запускается по запросу. Управление устройствами в GUI использует сериализованное состояние авторизации при работающем приёмнике. Для отзыва устройства через CLI требуется остановить принимающий экземпляр. Постоянные токены устройств не выводятся в журнал.

Приём по умолчанию ограничен размером 64 МиБ на снимок, двумя одновременными загрузками и 32 обработчиками запросов. Протокол ограничивает размеры служебных данных, время бездействия при загрузке до 30 секунд, полное время передачи до 240 секунд и время запроса сопряжения до 10 секунд. Приёмник допускает 16 попыток сопряжения в минуту. Счётчик хранится в памяти и сбрасывается при перезапуске. Передача идёт через HTTPS без перенаправлений. Облачного сервиса передачи снимков в проекте нет.

## Сохранение и восстановление на Android

Камера пишет во временный файл в закрытом хранилище приложения. При сохранении приложение назначает снимку постоянный идентификатор и имя, записывает выбранное местоположение, проверяет JPEG и вычисляет размер и SHA-256. Затем оно записывает намерение создать документ, создаёт точный путь в выбранной через SAF папке, сохраняет URI документа и копирует снимок. Статус `SAVED` и задание на доставку выбранному приёмнику записываются одной транзакцией после проверки сохранённых байтов. Только после этого временный файл можно удалить.

Повторная попытка может принять уже завершённую запись после проверки её байтов или переписать ранее записанный во внутреннем журнале неполный документ из временного файла. Если хранилище создало документ до записи URI в журнал, приложение принимает его только при записанном намерении создания, точном совпадении имени и совпадении полных байтов по размеру и хешу. При конфликте с неизвестной или неполной копией исходный временный файл сохраняется. Его можно экспортировать из настроек. Для восстановления выберите исходную папку, верните разрешение на доступ или освободите место и повторите сохранение.

SAF не предоставляет одинаковых гарантий синхронизации, переименования и атомарной публикации для всех провайдеров. Если провайдер не позволяет прочитать результат для проверки, снимок остаётся во внутреннем временном хранилище. Сценарии сбоя, отзыва разрешений и нехватки места зависят от провайдера.

Смена основной папки применяется к новым снимкам. Поворот экрана и возврат из фона сохраняют активный сеанс в памяти, а после остановки процесса нужно подтвердить выбор папки снова. Удаление приложения удаляет его метаданные, настройки и временные файлы. Снимки в выбранной пользователем папке хранятся отдельно.

## Доставка и удаление локальной копии

Синхронизация выключена по умолчанию. Новое задание связывается с выбранным приёмником во время съёмки при включённой синхронизации. Ранее сохранённые снимки добавляются в очередь по явному выбору папок. Передача начинается после проверенного локального сохранения. Операции приложения и WorkManager получают задания из общей очереди Room. Случайный идентификатор и десятиминутный срок закрепления защищают от повторной обработки одним и тем же исполнителем. После остановки процесса повтор может ждать истечения этого срока. Приёмник проверяет идентификатор снимка и квитанцию, чтобы повторная отправка не создавала второй файл.

При временной ошибке отправка повторяется с задержкой. Восстановление подключения сбрасывает задержку ожидающих заданий, а кнопка повтора возвращает в очередь и задания с исправленной постоянной ошибкой. Выключение синхронизации останавливает запуск новых запросов. Уже начавшаяся отправка может завершиться. При замене компьютера решение об отмене старой очереди подтверждает пользователь. Задания сохраняют привязку к исходному компьютеру.

При установлении соединения Android выбирает доступный Wi-Fi или Ethernet для локальных сокетов и DNS и отключает HTTP-прокси для этого транспорта. Проверка доступности интернета для выбора локальной сети и повторной передачи не требуется. Фоновые запуски выполняет планировщик Android.

Настройка «Удалять фото с телефона после передачи» выключена по умолчанию. При включённой настройке приложение записывает подтверждённую квитанцию и намерение удалить локальную копию одной транзакцией. Перед удалением повторно сверяются размер и SHA-256 файла по сохранённому URI. При несовпадении или ошибке доступа удаление остаётся незавершённым, а статус доставки сохраняется. Удаление можно повторить из настроек. Незавершённые операции проверяются при следующем запуске, если настройка включена.

## Сертификаты, учётные данные и обновления

При подключении Android проверяет срок действия TLS-сертификата и его SHA-256-отпечаток, полученный при сопряжении. При смене адреса проверяется также идентификатор приёмника. Приложение хранит учётные данные в зашифрованном виде с AES-GCM и ключом Android Keystore. Правила резервного копирования и переноса исключают данные приложения. После утраты ключа требуется повторное сопряжение.

Проверка обновлений Android обращается к GitHub Releases по команде пользователя. Перед запуском системного установщика приложение сверяет SHA-256 загруженного APK с данными релиза. Съёмка, сопряжение и передача снимков в локальной сети доступны без этого обращения.
